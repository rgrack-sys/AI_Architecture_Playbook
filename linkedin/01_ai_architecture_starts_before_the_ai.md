# AI Architecture Starts Before the AI

One of the biggest mistakes I see in AI architecture happens before anyone writes a prompt.

We start with the technology.

“We need an agent.”

“We need RAG.”

“We should use this model.”

“We need an AI platform.”

Maybe.

But none of those things is an architecture requirement.

I’ve been refining a sequence I increasingly believe should drive enterprise AI architecture:

**Business problem → Outcome → Process → Decisions → Evidence → Controls → Architecture → Technology**

The order matters.

Start with the business problem.

What outcome are we trying to change?

What process produces that outcome?

Where in that process are decisions actually being made?

What evidence should those decisions rely on?

What constraints, permissions, regulations, or business rules govern those decisions?

Only then should we start designing the AI architecture.

And technology comes last.

This becomes even more important with agentic systems.

An agent can make a badly designed process operate faster.

It can automate a decision that should never have been automated.

It can scale an architectural mistake remarkably efficiently.

AI architecture should not begin with:

**“What can the model do?”**

It should begin with:

**“What does the business process need to accomplish, and where can machine reasoning improve it?”**

Technology should implement the process.

The technology should not determine the process.
